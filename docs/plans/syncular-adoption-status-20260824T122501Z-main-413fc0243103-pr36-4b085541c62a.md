## Already adopted from Syncular

The report identifies two direct adoptions, both completed and verified in Palladium core.

### 1. Fail closed when engine transactions are unavailable

**Syncular practice:** require transactional, serialized storage for a push; do not apply a multi-operation commit sequentially when the required guarantees are unavailable.

**Palladium adoption:** `PalladiumEngine.tx()` and `PalladiumEngine.applyRemote()` now reject an adapter without transaction capability before advancing HLC or modifying data. The former sequential fallback was removed.

**Why it matters:** a failure during the second operation of a batch can no longer leave the first operation durable without its corresponding complete change or cursor checkpoint.

**Report evidence:** comparison report sections “P0: atomic and serialized commit finalization” and “Completed implementation: Fail closed without transaction support.” The report records regression coverage for rejected two-table local and remote transactions, with both tables remaining empty.

**Keep:** this is a correct, direct adoption. The report says Node, browser, and Capacitor SQLite adapters already satisfy the required transaction capability, while lower-level storage and migration APIs may continue to use plain adapters.

### 2. Deterministic response-loss and truncated-response scenarios

**Syncular practice:** exercise a defined transport fault vocabulary, including response loss after server processing and truncated responses.

**Palladium adoption:** core sync tests now use the existing injected-fetch seam to cover:

- A response lost after the server observes a change. The durable outbox retains the same change ID, a restarted transport retries it, and acknowledgement clears the outbox.
- A truncated downlink response. No change is applied and no cursor advances; a valid replay applies exactly one row.

**Why it matters:** these cover durable replay identity and the no-advance-on-incomplete-downlink invariant without introducing an unnecessary new test framework.

**Report evidence:** “Completed implementation: Deterministic sync fault scenarios.” The report records successful core tests, typecheck, formatting/linting, Rust tests, and real TypeScript-to-Rust e2e checks.

**Keep:** retain the small local fault helper for now. The report specifically says a generalized fault controller is justified only once multiple scenarios need the same reusable fault vocabulary.

## Important Palladium strengths—not Syncular adoptions

The report does not recommend replacing these Palladium capabilities with Syncular equivalents:

| Palladium capability | Decision |
|---|---|
| Per-column HLC LWW, buffered updates for absent rows, and delete tombstones | Preserve. This is stronger for offline peer convergence than Syncular's server-authoritative `baseVersion` conflict model. |
| Versioned client SQL migrations and seeds | Preserve. Do not replace with Syncular's reset/rebootstrap model. |
| Habitat/Atrium workspace membership, root/child ACL inheritance, per-member grants, revocation purges, and blob ACL inheritance | Preserve. This is more product-specific than Syncular's generic scope system. |
| Durable client outbox, stable change IDs, poison quarantine, and real TS-to-Rust e2e | Preserve and strengthen. These are existing useful Palladium foundations. |

## Practices still to adopt

### P0: replace HLC history cursors with a server-assigned append sequence

**Status in the comparison report:** not adopted; deliberately not partially implemented.

This is the report's highest-priority production correctness gap. Atrium history is queried by `hlc_key > after`, while the cursor is derived from client HLC. A valid older-HLC offline change appended after a consumer has advanced past a newer HLC can be skipped forever.

Required clean cutover:

1. Persist a server-assigned `append_seq` or equivalent commit sequence in Atrium history.
2. Query history by `append_seq > after`, not HLC.
3. Return a response-level high-water cursor even if ACL filtering yields no visible changes.
4. For limited pages, return the sequence at the last fully scanned history position—not the global maximum.
5. Persist the sequence cursor in `SyncTransport`.
6. Keep HLC solely for LWW conflict resolution.
7. Migrate or explicitly invalidate persisted HLC cursors.
8. Add Atrium database, HTTP, and TS-to-Rust e2e coverage for an HLC-100 consumer receiving a subsequently appended HLC-50 change exactly once.

The report classifies this as a production correctness requirement, not an optimization.

### P1: schema-aware durable outbox compatibility

**Syncular practice:** encode queued operations against the active schema at send time; classify operations targeting removed tables or columns as stable terminal incompatibilities.

**Palladium gap:** serialized queued wire operations have no schema version/fingerprint. After a table or column removal/rename, an incompatible operation can retry indefinitely.

Recommended adaptation:

- Persist a schema fingerprint or version with each queued change.
- Validate each queued operation against the active schema before POST.
- Move incompatible operations into a terminal state with a stable error identity.
- Preserve compatible queued operations with their original IDs and HLCs.
- Test restart after a migration containing both compatible and incompatible queued writes.

Do not adopt Syncular's full reset/rebootstrap model; Palladium's SQL migrations remain the preferred client schema capability.

### P1: concurrent duplicate-post finalization coverage

**Syncular practice:** lock the partition, recheck idempotency after locking, atomically apply, append, and store the canonical idempotency result.

**Palladium state:** stable IDs, durable outbox replay, and server `INSERT OR IGNORE` give useful idempotency, but the report calls concurrent duplicate POST behavior less rigorous.

Add a real Atrium regression proving that concurrent duplicate deliveries persist one append sequence and produce one canonical result.

### P1: adversarial authorization and validation coverage

Do not replace Atrium's domain ACL with Syncular's generic scope system. Strengthen the evidence for the existing model with tests for:

- Scope or ownership-field manipulation.
- First-insert ownership races.
- Cross-workspace identifiers.
- Concurrent invite acceptance.
- Rejected changes leaving no stale record metadata.

### P1: TS/Rust language-neutral protocol conformance vectors

**Syncular practice:** shared scenario catalog and golden wire vectors validate valid decode, decoded structure, byte-identical re-encoding, invalid input, and stable error codes across implementations.

**Palladium gap:** TypeScript `WireChange`, Rust `Change`, HLC serialization, Atrium envelopes, malformed change errors, and purge/event envelopes have no shared language-neutral vector gate.

Add committed fixtures consumed by both TypeScript and Rust test suites.

### P1: reusable deterministic transport fault controller

The report intentionally adopted only two focused scenarios, not Syncular's whole testing utility. Once core and integration suites share several fault cases, add a reusable controller covering:

- Request drop before processing.
- Response drop after processing.
- Request duplication.
- Response truncation.
- Later blob download and signed-URL failures.
- Seeded reproducible corruption/truncation locations.

### P2: explicit clock seams and timer-free tests

**Syncular practice:** tests advance an injected domain clock rather than sleeping.

Adopt clock seams for HLC wall time, outbox/quarantine timestamps, and token or lease expiry. Add deterministic `syncOnce()`, `syncUntilIdle()`, readiness barriers, acknowledgement hooks, and reconnect hooks. Remove timer-based unit behavior where feasible.

### P2: in-process Atrium router protocol tier

The report recommends a middle test tier that invokes the real Axum router in-process. Keep the existing real-process e2e suite for binary packaging and lifecycle coverage, and use the in-process tier for deterministic protocol edge cases.

### P2: operational and feature breadth

Adopt only after append-sequence catch-up exists:

- Realtime as a wakeup signal that initiates ordinary HTTP history catch-up; do not use websocket delivery as the sole source of truth.
- Network blob transport around Atrium's existing ACL-gated PUT/GET routes, including upload-before-reference validation, parent ACL checks, retries, and orphan cleanup.
- Informational load testing for concurrent-client count, push/pull throughput, p50/p95/p99 latency, retries, conflicts, quarantines, duplicate delivery, and separate SQLite/Postgres behavior. Make budgets blocking only after a stable baseline.

Scoped/windowed partial replicas are broader Syncular functionality, but require a separate protocol design for subscription identity, scope changes, pagination completeness, grant backfill, revoke purge, and cursor advancement. They are not a direct next-step copy.

## Recommended adoption order

1. **P0:** append sequence, clean cursor migration, ACL-filtered empty-page behavior, and late-old-HLC e2e regression.
2. **P1:** concurrent duplicate POST test, outbox schema compatibility, adversarial ACL tests, and TS/Rust protocol vectors.
3. **P2 testing discipline:** shared fault controller, injected clocks, timer-free synchronization APIs, and in-process router tests.
4. **P2 breadth:** realtime wakeups, network blobs, and informational load reporting.

## Bottom line

Per the comparison report, Palladium has already adopted the two immediately safe Syncular practices: **fail-closed engine transactions** and **deterministic response-loss/truncated-response testing**.

The primary remaining adoption is not a collection of small test improvements: it is the coordinated **server append-sequence cursor migration**. That change must precede production use because it closes a demonstrated history-loss path. The remaining recommendations improve compatibility, idempotency confidence, cross-language protocol safety, deterministic testability, and operational maturity without discarding Palladium's stronger offline merge semantics, migrations, or Habitat-specific ACL model.
